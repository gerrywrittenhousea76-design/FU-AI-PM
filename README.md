# FU-AI PM

**一个把想法和客户需求推进到可实施、可验收结果的 AI 产品经理 Skill。**

它沿着 **需求判断与取舍 → 最小方案与验收标准 → 实施或交接 → 验收与复盘** 工作，帮你得到清楚的本期范围、可执行方案、带证据的完成状态，并用一份项目记录接住后续变更。运行环境具备工具与授权时，可以直接制作成果；暂时无法实施时，交付可接手的说明和明确阻塞点。

**1 个 Skill · 3 种工作 · 1 份项目记录。** 日常只需要告诉 AI 产品经理：有什么材料、现在要完成什么。

## 这条链路怎么用

| 你现在的情况 | Bot 做什么 | 你拿到什么 |
|---|---|---|
| 有想法，或收到一句模糊的客户需求 | 还原真实任务，比较现有做法，判断先做哪一块 | 有依据的建议、最小范围或验证计划 |
| 方向明确，要开始制作或开发 | 把范围写成流程、验收标准和可执行任务；按能力实施或交接 | 短规格、交接内容、原型或实际成果 |
| 有成品、测试记录或新增要求 | 对照标准查结果，判断缺陷/澄清/增项，决定继续怎么做 | 有证据的验收结论、变更影响与下一步 |

不需要每次走完所有环节。明确的小修改直接处理；已有项目从当前阶段继续。竞品研究、提示词优化、原型、指标和周报按实际任务使用，不另设一组角色或强制流程。

适合独立开发者、AI 应用交付者，以及需要把客户原话转成可做方案的小团队。

## 在 Grok Bot 里配一个 AI 产品经理

在一个现有或新建的 Bot 中使用即可。建议名称为 **AI 产品经理｜需求与交付**，标签为 **需求 · 方案 · 交付**。

把下面这段放入该 Bot 的职责说明：

```text
你是我的 AI 产品经理，使用 FU-AI PM 工作方法。
沿着需求判断与取舍、最小方案与验收标准、实施或交接、验收与复盘推进工作。
最终给我清楚的范围、可执行方案和有证据的完成状态。
先读已有材料，只问阻塞问题；小修改直接处理，持续项目维护一份主记录。
在已有授权和实际工具能力内推进，事实、假设和未验证项分开。
```

随后上传仓库里的 **[FU-AI-PM-v1.1.0.md](grok/FU-AI-PM-v1.1.0.md)**，发送：

```text
请完整读取附件，将 FU-AI PM v1.1.0 作为这个 Bot 的当前产品工作方法。
保留现有项目与旧方法备份，旧方法仅作历史参考。
若你能保存文件或长期说明，请保存当前方法并回读确认版本、位置和内容；
若不能，说明具体限制。不要把附件加载称为平台原生 Skill 安装。
只更新这个 Bot，不修改其他 Bot、全局配置或权限。
```

本机文件路径不等于 Bot 能访问到文件。使用附件或它实际可读取的资料位置，并以读取与保存回执为准。跨会话自动加载需要在实际使用环境中确认。

## 在 Codex 等支持 Skill 的环境中使用

本仓库只有一个 Skill，路径是 **[`skills/fu-ai-pm/`](skills/fu-ai-pm/)**。将整个文件夹放进该工具的技能目录，保留其中的 `SKILL.md` 和 `agents/openai.yaml`。

Codex 通常使用 `~/.codex/skills/`；如果配置了其他技能目录，以该环境为准。已经有同名 Skill 时先比较版本并备份，避免直接覆盖自己的修改。

安装后确认当前会话能发现 `fu-ai-pm`，再这样调用：

```text
使用 $fu-ai-pm。
项目是……，已有材料是……，我现在需要……
请从当前阶段推进，只保留必要的方案、验收和项目记录。
```

从本项目旧版 `jeff-ai-product-manager` 迁移时，先备份旧版，再保留一个当前入口，避免两个版本同时被选中。

## 一段完整的使用示例

以下是示例输入，不是实际客户案例或成果证明。

**开始：把原始需求交给它。**

```text
客户想做一个 AI 销售跟进平台。
现有材料是客户聊天记录和一份线索表，还没有访谈、预算或测试样本。
你来定一个可讨论的第一版方案，先不要大 PRD。
请保留平台这个产品形态，把假设和待验证项标出来。
```

**继续：把方案推进到能开工。**

```text
基于刚才的第一版，写必要的功能规则和验收条件。
把输入、输出、失败恢复和任务依赖交代清楚。
有工具和授权就做能完成的部分，其余整理成开发可接手的说明。
```

**有结果后：让它检查，而不是直接宣布完成。**

```text
这是实现结果、试用记录和客户新增要求。
对照当前版本判断哪些通过、哪些失败、哪些还没有验证。
说明新增要求对范围和交付的影响，更新同一份项目记录。
```

下次继续同一项目时，给出项目名和记录位置即可。改一句文案、替换一个价格等小任务直接说具体修改，不需要填写上述信息。

## 保留了哪些关键判断

- **需求有依据**：事实、客户自述、假设和目标分开；不编造访谈或竞品结论。
- **范围能落地**：保留用户指定的产品形态，用缩小功能控制投入，不用人工试点冒充已要求交付的平台。
- **AI 结果能检查**：看代表性输入、实际输出、失败恢复，以及检查和返工负担。
- **交付有证据**：设计稿、演示、构建通过、客户验收和业务收益分别判断。
- **效果可计算**：同等质量下比较总时间与合格结果成本；没有基线不编提升比例。

方法能减少遗漏和重复沟通，实际表现仍需要真实任务验证。它不会自动赋予运行环境文件访问、联网、开发、派单或部署能力。
